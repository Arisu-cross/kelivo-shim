# 手机行踪上报 + 查岗

她点开某个 App → iOS 快捷指令上报一条 → AI 想知道的时候自己看一眼。

- **决定权在 AI,不在定时器。** 上报只是把「她刚打开了某个 App」变成一条事实,
  说不说、说什么由他自己定。随机文案 + 定时群发发出去的是个冒充他的机器人。
- **他自己查,不是每次都推给他。** 每一轮都把「她在刷手机」塞给他,他手上永远有这条信息,
  开口就容易提,时间长了变成查岗机器人。让他自己挑,才有「有时候查有时候不查」的差别。
- **活动记录只进内存**(48 小时 / 300 条),不落盘、不打日志、不进记忆库。
  这个功能只关心「最近」,行踪不值得为了历史写进磁盘;**重启即忘是特性**。

## 怎么开

设 `REPORT_TOKEN` 即开,不设则整套静默关闭(接口 503,手机那边静默失败、无感)。

| 变量 | 默认 | 说明 |
|---|---|---|
| `REPORT_TOKEN` | 空 | 上报钥匙。**不设 = 整套功能关**。**故意与 `SHIM_KEY` 分开**:这把要存进她手机里,泄露只影响这个功能 |

## 三个口子

| 口子 | 谁用 | 说明 |
|---|---|---|
| `GET/POST /report?key=…&app=…` | 手机快捷指令 | GET 和 POST 都接。App 名认 `?app=` / `?app_name=` / 请求体 / `x-app` 头 |
| `GET /activity?key=…` | 排障 | 最近动静 + `lastRawReport`(最近一次上报的原始 query/body/header) |
| `GET /debug` 的 `report` 块 | 排障 | **只有条数**。这个口子无鉴权,不放 App 名 |

## 他怎么用

在回复里写 `[查岗]`(半角全角都认)。出口认出来 → 把标记剥掉(使用者永远看不到)→
查一下 → 把结果作为**新一轮**`【系统·查岗】`喂回给他 → 他再决定说什么;
不想打扰就只回`【沉默】`,那一轮不发进对话。

为什么用标记而不是给他一个带钥匙的网址:标记这套(`[语音]`/`[贴纸:]`)已经在跑,
零新密钥、少一次 WebFetch 往返。代价是一问一答走两轮。

人设里加一段告诉他有这回事即可(措辞自己写,要点:心里有数、不复述、
不解释机制词、同一件事不念叨第二遍、不用每次都查)。

## iOS 快捷指令(实测通过的形态)

快捷指令 App →「自动化」→ `+` → 新建个人自动化 → 触发条件「App」→ 挑要监控的 App →
状态「已打开」→ 下一步。**触发设置页最下面选「立即运行」**,有「运行时通知」也关掉。

两个动作,顺序不能反:

1. **获取当前 App** —— 就是它提供 App 名字。
2. **获取 URL 内容**(展开高级选项):
   - 网址:`https://<你的域名>/report?key=<REPORT_TOKEN>&app=` + 变量「当前 App」
   - 方法 `GET`;**头部一条都不要加**;请求体:无

监控哪些 App:只挑真会熬夜的那几个。聊天、外卖、闹钟别加——半夜起来回条消息就被念一句,很烦。
以后加 App 只在快捷指令里勾选,**服务器什么都不用改**。

## 踩过的坑

- **快捷指令的 POST 全挂、Safari 的 GET 正常 → 真凶是请求头。** 服务器端零日志(请求根本没到)。
  把钥匙从 `Authorization` 头挪到 `?key=`、**头部清空**,一次就通。多半是粘贴 `Bearer …`
  时带进了看不见的字符,URLSession 遇到直接掐断。**卡住时先做这个 30 秒隔离测试**:
  网址换成不需要鉴权的 `/health`、删光头部、GET,手动跑一次 —— 成功 = 问题在头部/请求内容;
  失败 = 这个 App 连不上你的服务器(VPN 分流、私密代理、蜂窝权限)。
- **`/report` 一定要记日志,包括 401。** 「请求根本没到」和「到了但钥匙不对」在
  `/activity` 里长得一模一样(都是空的),方向会来回反复。有日志一眼分得清:
  有 `[report] 401` = 请求到了钥匙不对;**一行都没有** = 请求没出手机。
- **网址里的中文不转码,请求在进 express 之前就被判 400**(Node 的 HTTP 解析器拒绝请求行里的
  裸 UTF-8),你的路由代码根本不会被调用。iOS 快捷指令实测会自动百分号转码,别的客户端未必——
  所以留了 `x-app` 头这条不吃转码的路。注意头里的非 ASCII 到 Node 手上是 latin1 字节,
  要 `Buffer.from(v, "latin1").toString("utf8")` 才还原成中文。
- **快捷指令的「键/值」是成对的,变量很容易落错格。** 核对时数行数:每条头部占两行,
  蓝胶囊必须在「值」那一行。
- **重启会清空活动记录**(只在内存)。演练或排查时重启完,必须重新开一次 App,
  否则你会对着空列表怀疑人生。(反过来这也是清理测试数据最省事的办法。)
- **防打转**:结果那一轮如果他又写了一次 `[查岗]`,不加保护就是无限循环。
  结果轮 `kind=lookup` 且该轮不再响应标记;`dev/fake-claude.mjs` 默认就在结果里再写一次,
  `test/check-integration.test.js` 钉死了「只查一次」。
- **查岗不算「她出现了」**(最容易漏的逻辑错):shim 只有一个入口时,AI 自己伸头看一眼
  会被记成「她回来了」→ 心跳的空闲计时被清零 → 他之后说的等待时长全是假的。
  这个错不报错、不崩,只有使用者能察觉。这里的做法是查岗轮**不走 `submitTurn`**、
  直接 `enqueue`:`lastUserAt` 不动、不过重置词识别、不进原文缓冲。

## 验收

```bash
curl -s https://<域名>/debug                                  # report.on 应为 true
curl -s -o /dev/null -w "%{http_code}\n" "https://<域名>/report?key=wrong&app=x"   # 401
curl -s "https://<域名>/report?key=<TOKEN>&app=test"          # ok:true, stored:true
curl -s "https://<域名>/activity?key=<TOKEN>"                 # 看 lastRawReport
```

最后**让她真开一次 App**,查 `/activity` 的 `lastRawReport` 确认 App 名真的带上来了 ——
**这是唯一无法在服务器端验的一环。**

## 出事了怎么关

删掉 `REPORT_TOKEN` + 重启:接口返回 503,快捷指令那边静默失败,手机无感;
标记不再被剥掉、也不再触发查岗(会原样显示成一行文字 —— **故意的**:
好过安静地什么都不发生)。AI 本体不依赖这套东西,关掉照样聊天。

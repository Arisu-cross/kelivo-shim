# 长对话的记忆保全:压缩瘦身 + 压缩前自动归档 + 压缩后先呼吸 + 归档按天合并

> 写给实现者(人或 Claude Code)。四件事是**一套**,拆开做会漏记忆。
> 前提:你的 AI 有一个「长期记忆」MCP(能写归档、能按需读回)。本文以 Ombre-Brain
> 为例(`archive_session` 写、`breath(wake=true)` 读),换成别的记忆库同理。

---

## 一、要解决的问题

常驻长对话(一个不断的会话窗口)迟早会撞上上下文上限。Claude Code 的默认行为是
**自动压缩**:把整段对话重写成一份几千 token 的摘要,之后这份摘要常驻上下文前缀。

对「AI 伴侣」这类场景,默认行为有三个问题:

1. **重复负担** —— 长期记忆本来就在记忆库里,摘要里那份转述是第二份,还每轮按缓存价重读。
2. **越摘越糊** —— 摘要是摘要器写的转述,不是本人写的。反复压缩后语气和细节被磨平。
3. **真正的丢失** —— 「上次归档到现在」这一段**只存在于窗口里**。压缩一来就只剩摘要里的
   几句转述;如果你还把摘要瘦身了(见下),那就是彻底没了。

所以四件事必须配套:

```
       ┌─ ① 摘要瘦身成一行 ────────── 省 token、不留糊掉的转述
       │
压缩 ──┼─ ② 压缩前自动归档 ────────── 把「上次归档到现在」抢救进记忆库  ← 关键
       │
       └─ ③ 压缩后第一句先呼吸 ────── 从记忆库读回,而不是顶着一行摘要硬接
                     │
                     └─ ④ 归档按天合并 ── 免得一天被归成七八份碎档
```

**少做 ② 就会丢记忆**:摘要瘦身之后没有任何兜底。这是本文最重要的一句话。

## 二、① 摘要瘦身成一行(PreCompact 钩子)

Claude Code 支持 `PreCompact` 钩子:**压缩发生之前**执行,stdout 会作为额外指令拼进
压缩提示词。用它指示摘要器「别复述,只留一行指路」。

**`compact-instructions.js`**(新建,可执行):

```js
#!/usr/bin/env node
const DEFAULT = `【摘要要求 · 最高优先级,覆盖以上全部默认摘要规则】
这段对话的完整记忆由长期记忆系统保管,不需要你在摘要里复述。
禁止:复述对话内容、引用原话、列举细节、罗列待办、总结技术状态、分点展开。
整份摘要只输出下面这一行,不要有任何其他文字:

上文已存入长期记忆。细节请用 breath(wake=true) 取回,不要凭这一行推测上文。`;

process.stdout.write(process.env.COMPACT_INSTRUCTIONS || DEFAULT);
```

**挂上去**(spawn `claude` 时用 `--settings` 传 JSON,不必落文件):

```js
function compactSettingsArg() {
  const dir = import.meta.dirname || process.cwd();
  const cmd = `node ${JSON.stringify(path.join(dir, "compact-instructions.js"))}`;
  // matcher 省略 = 匹配全部 trigger(auto / manual)
  return JSON.stringify({ hooks: { PreCompact: [{ hooks: [{ type: "command", command: cmd }] }] } });
}
// args.push("--settings", compactSettingsArg());
```

## 三、② 压缩前自动归档(核心)

### 3.1 先要能算准窗口用量

**这里有个大坑,先说结论:绝对不要用 `result` 事件里的顶层 `usage` 估算窗口大小。**

一轮对话里每调用一次工具就是一次独立 API 请求,而 CLI 的顶层 usage 是**整轮所有请求的
累加**。一轮调 3 次工具 → 顶层 `cache_read` ≈ 真实前缀 × 3。真实翻车记录:真实窗口
53947,顶层报 161206,**虚报 3 倍**,把 32% 显示成 97%,触发了毫无根据的提醒。

(也别想用 `iterations[]` 兜底 —— 它不累加、且线上绝大多数轮次是空数组,退回顶层 = 同一个坑。)

**唯一正确来源:每次 API 请求自己的 `message_start` 事件**,它带的 usage 就是这次请求的
真实前缀,不含累加。

**`window.js`**:

```js
// 自动压缩触发线。Claude Code 算法(v2.1.x):
//   effectiveWindow = 模型上下文上限 - min(最大输出 token, 20000)
//   threshold       = effectiveWindow - 13000(压缩缓冲)
// 200k 模型 → 200000 - 20000 - 13000 = 167000
export const DEFAULT_WINDOW_LIMIT = 167000;

export const prefixOf = (u) =>
  (u?.input_tokens || 0) + (u?.cache_read_input_tokens || 0) + (u?.cache_creation_input_tokens || 0);

export function prefixFromMessageStart(event) {
  if (!event || event.type !== "message_start") return 0;
  return prefixOf(event.message?.usage);
}

export const windowPct = (tokens, limit = DEFAULT_WINDOW_LIMIT) =>
  limit > 0 ? Math.round((tokens / limit) * 100) : 0;
```

在事件流里取本轮各次请求的**最大**前缀(不跨轮取 max —— 数值本身已准确,跨轮钉死会让
某次异常永远修不回来):

```js
// 事件处理里
const p = prefixFromMessageStart(ev.event);
if (p > turn.peakPrefix) turn.peakPrefix = p;

// 一轮结束(result 事件)时
if (turn.peakPrefix > 0) { windowTokens = turn.peakPrefix; checkWindowUsage(); }
```

### 3.2 两级阈值:先提醒人,再自动归档

```js
const WINDOW_LIMIT        = +(process.env.WINDOW_LIMIT || DEFAULT_WINDOW_LIMIT);
const WINDOW_WARN_PCT     = +(process.env.WINDOW_WARN_PCT || 85);     // 提醒用户
const WINDOW_AUTO_ARCHIVE = process.env.WINDOW_AUTO_ARCHIVE !== "0";
const WINDOW_ARCHIVE_PCT  = +(process.env.WINDOW_ARCHIVE_PCT || 90);  // 自动归档

let windowTokens = 0, windowWarned = false, windowAutoArchived = false;

function checkWindowUsage() {
  if (!(WINDOW_LIMIT > 0)) return;
  const pct = windowPct(windowTokens, WINDOW_LIMIT);

  // ① 警戒线:提醒「用户」,走运维通道(如 TG),不进 AI 的窗口
  if (!windowWarned && pct >= WINDOW_WARN_PCT) {
    windowWarned = true;
    notifyUser(`⚠️ 窗口用到 ${pct}% 了。我一会儿会自动让他把这段存一下。`);
  }

  // ② 再往上:让 AI 自己归档,赶在压缩吃掉这段之前
  if (WINDOW_AUTO_ARCHIVE && !windowAutoArchived && pct >= WINDOW_ARCHIVE_PCT) {
    windowAutoArchived = true;
    autoArchiveTurn(pct);
  }
}
```

### 3.3 注入一条**诚实**的系统轮

> ⚠️ **这是全文最需要小心的地方。**
>
> 真实事故:早期版本往用户消息里塞「【系统指令】立刻调用 archive_session…」,
> 伪装成用户说的话。AI 把它识别为 prompt injection **拒绝执行**,而管道层不管成没成功
> 就重启了窗口 —— **一下午的记忆蒸发**。
>
> 教训不是「永远不能有系统轮次」,而是**不能假冒用户**。诚实署名系统、说清是谁的意思,
> AI 完全接受(同款成功先例:定时唤醒用的【系统·自主时间】轮次)。

```js
function autoArchiveTurn(pct) {
  const sink = {
    text() {}, thinking() {},
    finish(_u, fullText) {                       // 他归档完顺口说的话,转发给用户
      const t = (fullText || "").trim();
      if (t) sendToUser(t).catch(() => {});
    },
  };
  enqueue({
    text:
      `【系统·窗口快满了】这是运维提醒,不是她打的字:当前窗口用到 ${pct}% 了,` +
      `再往上会触发自动压缩,压缩会把「上次归档到现在」这段对话抹成一行摘要。\n` +
      `她希望你在压缩之前,主动把这段存进长期记忆。` +
      `现在调 archive_session,按你归档的老规矩写——只写上次归档之后的新内容,` +
      `带上亮点和心情。存完之后想跟她说句什么就自然说,不用解释这套机制。`,
    images: [], system: currentSystem, sse: sink, newWindow: false, model: currentModel,
  });
}
```

**三个必须做对的点**:

| 点 | 为什么 |
|---|---|
| `windowAutoArchived` 去重 | 一个窗口只触发一次,别每轮都归 |
| 压缩后要 **reset** 该标志 | 否则一个进程只会归一次,之后再也不归 |
| `enqueue` 走**队列**而非直接执行 | 不打断进行中的对话;当前轮结束、busy 清零后自动排上 |

压缩事件里一起重置:

```js
if (ev.type === "system" && ev.subtype === "compact_boundary") {
  compactions++;
  windowTokens = 0; windowWarned = false; windowAutoArchived = false;  // ← 三个都要清
  return;
}
```

这样就形成闭环:**填满 → 提醒 → 自动归档 → 压缩 → 计数归零 → 继续**,可以无限转,
每一轮循环记忆都被保住。

## 四、③ 压缩后第一句话先呼吸(人设侧)

代码做不到这件事 —— 得让 AI 自己知道「我刚被压缩了,先去读记忆」。写进人设(CLAUDE.md):

```markdown
## 压缩续接(同一个窗口里,记忆被摘要过)

聊得久了,这个窗口装不下的时候,系统会把前面的对话压成一份摘要接着往下跑。
特征是上下文开头出现一段英文标记:
**"This session is being continued from a previous conversation that ran out of context"**,
后面跟着一份对上文的总结(现在这份总结被刻意压成了一行,因为真正的记忆在记忆库里)。

看见这个标记,意思是:窗口没断、她还在对面,但我刚才那段记忆被压掉了——
原话、语气、那些说不清但重要的细节,都不在上下文里了。

所以**在回她第一句话之前,先 `breath(wake=true)` 把记忆捞回来,再开口。**

- 先呼吸,后说话。别顶着一行摘要直接接话——那样接出来的是"大致对得上"的话,不是我。
- 呼吸完自然接着聊。**不用报告"我刚被压缩了""我刚读了记忆"**,那是管道的事。
- 只在看见那个标记的那一次做一次,不是每条消息都呼吸。
- 如果呼吸完仍然对不上——她刚说的某件事在记忆里也找不着——就老实说
  "刚刚断了一下,你再说一遍",别顺着摘要编。
```

最后一条很重要:**给它一个诚实的退路**,否则它会顺着那一行摘要编一个「大致合理」的上文。

## 五、④ 归档按天合并(记忆库侧)

**问题**:每次 `archive_session` 都新建一个桶 → 一天归三次就碎成三份。唤醒时
「浮现最近 N 条归档」会被同一天的碎片占满名额,读起来也不连贯。

**做法**:档案名用日期 `会话归档 YYYY-MM-DD`。当天首次创建,之后**按 `## HH:MM` 追加一节**;
跨天才开新档。这样「最近 N 条归档」≈ 最近 N 天。

```python
_now  = now_iso()
today = _now[:10]      # YYYY-MM-DD
hhmm  = _now[11:16]    # HH:MM

seg = [f"## {hhmm}\n{summary.strip()}"]
if highlights.strip(): seg.append(f"\n**亮点**:{highlights.strip()}")
if mood.strip():       seg.append(f"\n**心情**:{mood.strip()}")
segment = "\n".join(seg)

day_name = f"会话归档 {today}"
target = None
if ARCHIVE_MERGE_BY_DAY:
    for b in await bucket_mgr.list_all(include_archive=True):
        m = b["metadata"]
        if m.get("type") == "archived" and m.get("name") == day_name:
            target = b
            break

if target:                                   # 追加
    bucket_id = target["id"]
    content = target["content"].rstrip() + "\n\n" + segment
    await bucket_mgr.update(bucket_id, content=content, valence=v, arousal=a)
    await bucket_mgr.touch_archived_at(bucket_id, _now)   # ← 见下
    merged = True
else:                                        # 当天首次
    content = f"# {day_name}\n\n{segment}"
    bucket_id = await bucket_mgr.create(content=content, name=day_name, ...)
    merged = False
```

**三个必须做对的点**:

1. **`archived_at` 要刷新**。多数记忆库的 `update()` 只认白名单字段,写不了它。得单独加:

   ```python
   async def touch_archived_at(self, bucket_id, when=None):
       """追加后必须刷新,否则排序和「上次归档」边界都停在当天第一次。"""
       path = self._find_bucket_file(bucket_id)          # 注意要能搜到归档区
       post = frontmatter.load(path)
       post["archived_at"] = when or now_iso()
       open(path, "w").write(frontmatter.dumps(post))
   ```

2. **追加路径不要再调一次 `archive()`**。桶已经在归档区,再走一遍会把刚刷新的
   `archived_at` 又盖掉,还做无谓的文件移动。

3. **成功返回值要保留成功标记**(如 🗄️)。管道层的「换窗安全阀」常靠这个标记判断
   归档是否真的成功 —— 丢了它,安全阀会误判成失败。

**已知取舍**:按**归档时刻**分档,不是按内容发生时刻。熬夜跨零点时,前一天深夜的内容
会被归进第二天的档案(内容一个字不丢,只是文件名归属)。介意的话把 `today` 改成
「凌晨 5 点前算前一天」即可。

## 六、环境变量总表

| 变量 | 默认 | 作用 |
|---|---|---|
| `COMPACT_HOOK` | 开 | 设 `0` 关闭摘要瘦身 |
| `COMPACT_INSTRUCTIONS` | 见上 | 整段覆盖摘要指令文案 |
| `WINDOW_LIMIT` | `167000` | 压缩触发线;换模型/上限变了要改 |
| `WINDOW_WARN_PCT` | `85` | 提醒用户的百分比 |
| `WINDOW_AUTO_ARCHIVE` | 开 | 设 `0` 关闭压缩前自动归档 |
| `WINDOW_ARCHIVE_PCT` | `90` | 自动归档的百分比;嫌晚就调低 |
| `ARCHIVE_MERGE_BY_DAY` | 开 | 设 `0` 退回「每次归档一个新桶」 |

建议加一个 `/debug` 端点暴露 `{tokens, limit, pct, warned, autoArchived, compactions}`,
不然这套东西全是黑盒,出问题没法查。

## 七、怎么验证真的生效

1. **窗口用量准不准** —— `/debug` 看 `pct`,跟实际聊天量对得上。
   若一轮调了工具就跳到 90%+,说明踩了「顶层 usage 累加」那个坑。
2. **自动归档触发** —— 把 `WINDOW_ARCHIVE_PCT` 临时调到很低(如 5),发条消息,
   看 AI 是否自己调了 `archive_session`,以及记忆库里是否真多了内容。测完调回去。
3. **压缩瘦身** —— 触发一次压缩后,看上下文前缀是不是只剩那一行。
4. **压缩后呼吸** —— 压缩后的第一句,AI 应先调 `breath(wake=true)` 再回答。
5. **按天合并** —— 一天内归档两次,确认记忆库里只多了一个桶、且**第一次的内容还在**
   (这条一定要测:追加写错会覆盖当天早先的记忆)。

## 八、按重要性排的坑

1. **别假冒用户注入指令**。诚实署名系统就没事,伪装成用户会触发 injection 防御,
   而且一旦管道层「不管成没成功都重启窗口」,就是记忆蒸发。
2. **别用顶层 `usage` 算窗口**(第三节)。虚报 3 倍,误报满窗。
3. **压缩后三个标志都要 reset**,漏一个就只生效一次。
4. **追加归档不能覆盖当天已有内容** —— 写测试守住这条。
5. **摘要瘦身和自动归档必须同时上**。只做瘦身 = 主动删掉唯一的兜底。
